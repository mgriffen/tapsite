tapsite

A real browser your agent can read the web with — running on your machine, answering to nobody's meter.

v5.2.0 55 tools · 12 categories MCP · stdio MIT Node ≥ 18
$ npx -y tapsite

tapsite drives Chromium locally and hands the results back as structured JSON. It renders JavaScript, keeps a logged-in session across calls, and reads what the page actually became — not what the HTML said before the browser got to it.

It is one dependency and a browser. There is no account, no key, and no request that leaves your machine except the one you asked for.

01Why this and not a hosted scraper

Firecrawl, Browserbase and Apify are good at what they do, and what they do is run a browser somewhere else. That difference decides three things.

Hosted scrapertapsite
Cost model Per page or per credit. Cost scales with curiosity. Your electricity. A 400-page crawl costs the same as one page.
Rate limits Plan-dependent. The ceiling arrives mid-job. None. The limit is your machine.
Authenticated pages Hand over credentials, or don't go. Log in yourself once, MFA and all. The session persists; the password never enters the chat.
Internal hosts Their network can't see your staging server. Yours can.
Where the page goes Through a third party. Nowhere.

The honest other side: a hosted service brings a proxy pool and someone else's uptime. If you are crawling a hostile site at scale from CI, buy that. This is for the work you do at your own desk.

02Three things it does that a text scraper structurally cannot

Design tokens, from computed styles

Not a guess from the stylesheet — the values the browser resolved, counted by how often they are actually used. Colours with usage counts, the real type scale, the spacing rhythm, shadows, breakpoints. Exports as W3C design tokens or a paste-ready :root block.

WCAG contrast on rendered pixels

Contrast checkers that read background-color miss gradients and images, and confidently pass white text sitting on a photograph. tapsite screenshots the page, hides the text, and samples the brightest pixel inside each text box — the true worst case.

This exact method caught a nav bar reported as 1.00:1 by computed styles and measured at 9.31:1 in reality, and separately caught hero text that computed as passing and was 3.5:1 on the gradient.

The same site, twice

Snapshot a page and diff it later, or diff two sites against each other. Design-token drift, layout changes, and new third-party scripts show up as a list rather than a feeling.

0355 tools, 17 of them by default

Registering every tool puts a large menu in your agent's context for what is usually one job. So the default profile is core, and the rest are one flag away.

$ npx -y tapsite --profile design
ProfileWhat it registers
core (default)Common reads, custom extraction, and the four composite workflows
designColours, type, spacing, shadows, icons, components, breakpoints, dark mode, tokens
contentMetadata, content, links, forms, a11y, tables, i18n, PWA, crawl, harvest
securityThird-party scripts, storage, headers, contrast, network capture, API schema
reconAll 55

Profiles combine — --profile design,content. The eight session tools that drive the browser and get you through a login are registered in every profile; no configuration can take away your ability to open a page.

05Hand the result to Claude Design

tapsite extracts a design system. Claude Design applies one. They compose.

Point tapsite at a site you need to match — a client's, a competitor's, your own before a rebuild — and get W3C design tokens out. Hand those to Claude Design and every deck, prototype and one-pager it makes comes back on-brand, without anyone eyedropping a screenshot.

07Get started

Add it to any MCP client. Claude Code, Claude Desktop, Cursor, Windsurf.

{ "mcpServers": { "tapsite": { "command": "npx", "args": ["-y", "tapsite"] } } }

First run downloads Chromium via Playwright, about 150 MB, once.
